## 保留的策略口径

- 候选取同花顺**当日实时涨停池**，按原始题材拆分；题材当前封板≥4只。
- 每题材按连板高度→首次封板时间取龙头/二龙头，至少二连板；跨题材按封板家数→高度→首封排序，去重最多3只；承接仍使用至少4点的原始分时预览相对价格，末点≥均值且≥最高值95%。
- 09:30–10:57允许新开仓；初始20万元、最多3仓、每笔约初始资金1/3。买入后第5个交易日或跌破入场价6%退出，遵守T+1；跌停/盘口不足不虚构卖出。
- 883958当时涨幅必须>0且数据当日、90秒内。缺失/过期禁止新开仓，已有持仓退出不依赖选股池或指数是否成功刷新。
- **开盘跌停家数≤10当前仍未启用**；旧文档曾声称启用，与旧实际代码不符。本次只修执行链与证据，不默默新增这个门槛。当前原策略亦未额外加入仅主板/ST过滤或六类买点。

## 成交近似与证据

1. 共享本轮候选、门控和腾讯L1报价，记录完整原始涨停池、请求/接收时间、各股票源行情时间。
2. 符合原条件且盘口可支持整笔买入时建立意向，**不在信号快照上立即记成交**。
3. 下一轮必须出现**源时间严格更新**的盘口；再次校验门控、候选是否仍有效、买卖一数量及价格。
4. 买入增加信号卖一价+0.2%的价格上限且不超过涨停；意向最长5分钟，信号/门控失效提前取消。卖出触发后保留退出意向，持续等待可成交买盘。
5. 买卖应用单边5bp滑点、向不利方向取整到分；佣金单边3bp、卖税5bp；不模拟最低佣金、全部交易所费用、真实排队或自身订单冲击。

`logs/sessions/YYYY-MM-DD/*.jsonl`记录：`POOL_SNAPSHOT`、`QUOTE_BATCH`、`SCAN`、`INTENT_CREATED/WAIT/CANCELLED`、`PAPER_FILL`、`NOTIFICATION_*`、覆盖心跳和结束状态。`PAPER_FILL`关联原信号事件ID及下一次报价，区别信号/意向/模拟成交。账户保存已成交意向ID防重；CSV是可恢复的次级导出，不作为成交唯一依据。

## 自动运行与恢复

- 08:00北京时间计划启动上午任务，09:15开始采集，11:31结束。
- 12:00计划启动下午任务，12:55开始，15:01结束；下午只处理退出、估值及待发送成交通知。
- 两段共用一个并发锁；GitHub排队仍无法保证准时，首轮/实际开仓覆盖时间和错误次数写入报告。
- 涨停池网络请求在后台线程进行，不再每轮拉起Python子进程；一批腾讯报价共享请求/接收时间，个股保留自己的源时间。池异常不作为无候选，且不能用旧池放行买入。
- 账号、通知发件箱、冻结证据和报告每5分钟由独立进程提交到 **s19-runtime** 分支，不阻塞扫描。午后/重启恢复同一权威账号，旧主分支account仅用于首次迁移种子，不清零持仓/资金。
- 检查点冻结日志的字节长度与SHA256，后台只上传该前缀；账号和证据对应同一时点。运行分支中的原始日志压缩为`.jsonl.gz`，保留最近7天，完整每段采集另存90天artifact。最终失败仍尝试保存，并另有90天Actions artifact。
- 通知使用已有`SERVERCHAN_SENDKEY`，发件箱持久化，成功才确认；失败退避重试，过时信号不补发为当前买点。发送成功与确认之间若进程崩溃仍可能重复，消息带记录编号供核对，不承诺严格一次送达。
- 恢复或远程保存失败明确报错，不回退到初始现金。数据短暂异常但恢复时结束状态为degraded；未恢复、没有上午开仓窗口覆盖、期末持仓估值缺失、已排队通知未送达或缺少所需通知配置仍失败。所有异常保留，不用绿色状态冒充零故障。
